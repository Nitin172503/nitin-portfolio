P03
Distributed Task Queue recently updated
Go · pluggable broker (memory/Redis) · Prometheus + Grafana · crash-safe with visibility-timeout reaper
expand

A priority-based distributed task queue in Go with a pluggable broker (in-memory or Redis — same application code), concurrent worker pool, and REST API. The live visualization in the hero is a small model of what this project actually implements.

Crash-safe by design. Redis dequeue is a single Lua script that atomically moves a task from pending into a processing ZSet scored by deadline — a task is never lost between "popped" and "marked processing." A background visibility-timeout reaper reclaims tasks whose workers died or hung, retrying them with the same priority-decay/max-retry path as an explicit failure. Handlers run with bounded timeouts and panic recovery so one bad task can't take down a worker.

Ships with a full observability stack — Prometheus metrics, alert rules, and a Grafana dashboard auto-provisioned via docker-compose. Operational hardening includes bearer-token auth, backpressure (queue-depth cap → 429), and a dead-letter path with an explicit retry endpoint.
